## Changelog

### ROM side

- Unofficial crDroid 9.20 / Android 13 build for Samsung Galaxy M11 (`SM-M115F`, `m11q`).
- Fix the stale VoWiFi status icon by using the actual IMS registration transport instead of the general mobile-data network type.
- Improve SIM phone-number display through standard Android subscription APIs. A number can only be displayed when it is supplied by the SIM or network.
- Add the restricted microG signature-spoofing patch, including modern `SigningInfo` support on user builds; runtime-tested. The existing microG package and signing-certificate restrictions are preserved.

### IMS, VoLTE and SMS

- Port the Samsung `M115FXXS5CWK3` IMS compatibility stack to crDroid Android 13.
- Support one active IMS subscription installed in either SIM1 or SIM2.
  - VoLTE and VoWiFi handovers have been runtime-tested on both SIM1 and SIM2, with ongoing calls and bidirectional audio preserved.
- Outgoing and incoming VoLTE calls, bidirectional audio and normal teardown have been validated on the tested setup.
- Support SMS sending and receiving, including the Samsung-to-Android IMS SMS bridge.
- Retain the stock 128-second SIP Timer F and the required Android 13 incoming-call and handover audio compatibility hooks.
- Concurrent dual-SIM/DSDS IMS operation is not supported or validated.

### VoWiFi

- VoWiFi has been validated on one SM-M115F using Taiwan Mobile and a known-good mobile hotspot in a single-active-SIM configuration.
- Validated operations include:
  - outgoing VoWiFi calls and incoming calls with bidirectional audio and normal teardown;
  - VoWiFi → VoLTE when Wi-Fi is switched off during a call;
  - VoLTE → VoWiFi when Wi-Fi is switched on during a call;
  - weak-signal departure from Wi-Fi, followed by continued LTE calling;
  - a new LTE call after the handover tests.
- The tested handovers preserved the ongoing call without redialing. Brief audio pauses may occur; no universal interruption-time guarantee is claimed.
- Preserve Samsung's modem-led legacy IWLAN handover and Android's deferred Wi-Fi shutdown. The retired AP-assisted handover experiment remains disabled.
- Remove the four old Taiwan-specific framework handover-blocking rules and use global stock-profile-backed Wi-Fi Calling availability.
  - This is configuration coverage, not a claim that every configured carrier has been tested or provisioned successfully.

## Known Issues and Limitations

- Emergency calling, including emergency calls over Wi-Fi, is not validated.
- Concurrent dual-SIM/DSDS IMS operation is not supported.
- Other carriers, other firmware/device variants, ViLTE and alternate audio accessories remain unverified.
- Wi-Fi Calling depends on carrier provisioning and a working path to the carrier's ePDG. The tested home Wi-Fi connection also failed incoming VoWiFi calls on Samsung stock, while an alternate mobile hotspot worked.
- Reconnecting to Wi-Fi does not guarantee an immediate mid-call return to VoWiFi. Stock signal hysteresis and ePDG timers may keep the call on LTE for a while.

## Installation

> [!IMPORTANT]
> Use a clean flash when changing ROMs. Back up your data and internal storage before wiping or formatting anything.

1. If the device was previously repartitioned, restore the stock partition layout using the stock ROM before installing a compatible TWRP recovery through Odin.
2. In TWRP, open **Wipe → Advanced Wipe** and wipe:
   - Dalvik / ART Cache
   - Data
   - Internal Storage
   - Cache
3. Flash the ROM ZIP intended for `m11q`.
4. Reboot back into TWRP.
5. If Google apps are not included in your ROM package, optionally flash a compatible Android 13 ARM64 GApps package before the first system boot.
6. Reboot to system, enable Wi-Fi Calling for the active SIM if desired, and allow IMS registration to complete.

Do not flash GitHub's **Source code** archives as a ROM. Use the flashable ROM ZIP supplied with the release.

### FBE Encryption / Decryption

Use only encryption/decryption add-ons verified for this crDroid build and recovery. Compatibility of the older CherishOS `Enable_FBE.zip` / `Disable_FBE.zip` attachments is not established for this release; do not assume they are interchangeable.

Do not flash both enable- and disable-encryption add-ons.

> [!WARNING]
> Switching between FBE and DFE requires **Format Data**.
> A normal factory reset is not sufficient.
> Formatting Data erases every file stored in internal storage. Back up first.
