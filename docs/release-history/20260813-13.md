## Changelog
### Device Side
- SELinux is now Enforcing
- /data is now file-based encrypted (FBE). A clean flash (format data) is required when coming from an older build.
  - TWRP cannot decrypt FBE, so internal storage shows scrambled filenames in recovery. To flash add-ons (GApps / KernelSU), use `adb sideload` or put the zip on a microSD / OTG drive.
  - TWRP backups of /data are useless after a format data: the keys live in the TEE and are destroyed with userdata.  Back up files from inside Android instead.
- Fixed FM Radio
- Fingerprint: M11 ships with either a Focaltech FT9362 or a Silead sensor. Both are now supported by the same build.
  - I don't own the model with Silead sensor, so feedback/testing would be greatly appreciated!
  - Use the following command to see which fp sensor model on your model (Need root)
    - adb shell su -c "getprop persist.vendor.runin.fp"

## Known Issues
- VoLTE is broken
  - Note: Voice calls cannot be verified on my end, as VoLTE is mandatory in Taiwan.
- Root status in KernelSU Next may vanish after a reboot
  - Currently investigating; this might be a side effect of FBE.
- Recording with the stock camera results in a resolution of 1080x1898, causing lag/stutter in the default video player
  - Workaround: Playback works smoothly in VLC.
- IPv6 tethering offload is broken
  - (Doubt anyone actually uses this, but good to know!)

## Installation
1. Flash Stock ROM & TWRP via Odin.
2. Flash the ROM zip, then reboot back into TWRP.
3. (Optional) Flash [BiTGApps Mini](https://bitgapps.io) and reboot to system.

### FBE Encryption / Decryption
Some recoveries, such as TWRP, may include built-in encryption/decryption addons that are not compatible with this ROM.
Use the ZIP files provided below to properly enable or disable FBE:

- `Enable_FBE.zip` - Enables file-based encryption (FBE).
- `Disable_FBE.zip` - Disables file-based encryption (DFE).

> [!WARNING]
> When switching between FBE and DFE, **Format Data is required**.
> A normal factory reset is not sufficient.
> Formatting data will erase all files stored in internal storage.

## Note for other maintainers
- PRODUCT_COMPRESSED_APEX is disabled on purpose.
  - Decompressed APEXes land on /data, and a loop device backed by an FBE /data fails dm-verity on this 4.9 kernel, causing a boot panic (metadata block corrupted in verity_work). Do not re-enable without testing a clean flash.

## Notes
- KernelSU Next is supported out of the box. Install the [v3.3.0 Manager APK](https://github.com/KernelSU-Next/KernelSU-Next/releases/tag/v3.3.0) to manage root access.
- Unlimited Google Photos storage is currently not working
  - This is an upstream/ROM-side issue. I tried to fix it but couldn't (just a silly quokka 🦘 doing my best).
