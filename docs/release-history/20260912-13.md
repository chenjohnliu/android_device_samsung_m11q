> [!WARNING]
> This is a release-candidate build for the Samsung Galaxy M11 (SM-M115F) only.
>
> SIM1 and SIM2 VoLTE/SMS have been validated separately. Concurrent dual-SIM/DSDS operation is not supported or validated.
> SMS sending and receiving are functional on the validated carrier configuration. Pure end-to-end SMS over IMS transport has not been validated.
> Emergency calling is not validated. Do not rely on this ROM for emergency communications.

## Changelog

### Samsung IMS / VoLTE

- Port the Samsung IMS stack to Android 13 through a modern MMTEL/SMS compatibility bridge.
- Enable bounded single-active-SIM VoLTE operation on either physical slot while rejecting stale, ambiguous, and DSDS slot mappings.
- Validate outgoing and incoming VoLTE calls, call teardown, and two-way in-call audio separately on SIM1 and SIM2.
- Add slot-aware IMS audio routing, including a narrowly gated single-active SIM2 fallback and deterministic call-state teardown.
- Enable SMS sending and receiving on SIM1 and SIM2 in the validated single-active configurations.
- Validate SIM2 outgoing SMS through an IMS attempt followed by the operator-requested automatic RILD2 fallback, and validate incoming SIM2 OTP SMS over IMS.
- Improve IMS recovery after SIM hot-swap and migration between SIM1 and SIM2.
- Fix the Samsung IMS SMS TP-Message-Reference property type so per-slot values are accepted by SELinux property validation.

### Bug fixes
- Restore bg-dexopt setting to everything (Report from tester)
  - To accelerate YouTube Morphe compile APK time
- Support microG signature spoofing
- Add LineageOS default web browser to ROM

## Not currently claimed or validated

- DSDS VoLTE
- Pure IMS-SMS delivery
- VoWiFi
- ViLTE
- Emergency calling
- Inter-RAT handover
- Other Samsung models, CSCs, carriers, or stock firmware versions
- Extended stress and long-duration call testing

## Known issues

- During one SIM2 IMS incoming-SMS test, RILD2 reported the same message again about five seconds later after an apparent delivery-report/message-reference mismatch. Android discarded the duplicate and displayed only one message.
- IPv6 tethering offload is not working; IPv4 hotspot/tethering works.
- Miracast interoperability is limited. One Windows 11 laptop with Intel Wi-Fi 7 could not establish a connection.
- This device supports only 2.4 GHz Wi-Fi, so wireless-display performance may be limited.

## Installation

1. Confirm that the device is an SM-M115F.
2. Back up all important data.
3. Install compatible stock firmware and TWRP if they are not already present.
4. In TWRP, use **Format Data** for this RC. Do not wipe EFS, modem, or persist.
5. Flash the ROM ZIP.
6. Reboot back into TWRP.
7. Optionally flash [BiTGApps Mini](https://bitgapps.io/).
8. Reboot to Android.

A clean flash is required for this release candidate. During development, persistent IMS/Telephony state left by experimental builds caused call failures even after the source changes were reverted. The exact contaminated `/data` item has not been identified.

### FBE Encryption / Decryption
Some recoveries, such as TWRP, may include built-in encryption/decryption addons that are not compatible with this ROM.
Use the ZIP files provided below to properly enable or disable FBE:

- `Enable_FBE.zip` - Enables file-based encryption (FBE).
- `Disable_FBE.zip` - Disables file-based encryption (DFE).

> [!WARNING]
> When switching between FBE and DFE, **Format Data is required**.
> A normal factory reset is not sufficient.
> Formatting data will erase all files stored in internal storage.
